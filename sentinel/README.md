# sentinel

Independent local implementation of the Ark Sentinel rule contract. `Store.Update` accepts the three Apollo JSON arrays used by Java `FlowRuleLoader`, `HotFlowRuleLoader`, and `DegradeRuleLoader`. The namespace is `<app>-sentinel`. `Engine.Admit` recognizes the exact Ark resource names: path, `no_login_all`, `hot_uid`, `hot_did`, `uid_<path>`, and `did_<path>`. The `no_login_all` rule checks the original path's statistics node, matching `ArkExtendFlowSlot`; it does not create one global counter. `WriteFallback` returns Java's HTTP 200 JSON response with code `100410` for flow/hot blocks and `100503` for degrade blocks.

This engine supports local QPS with Sentinel's default two aligned 500 ms samples, active request limits, per-value token refill, an aligned circuit-breaker statistics window with a single half-open probe, and `controlBehavior: 2` throttling with `maxQueueingTimeMs` (default 500). Queued requests reserve a paced slot and wait before admission; a request whose estimated wait exceeds the limit is blocked. It rejects unsupported associated/chain strategy, warm-up (`controlBehavior: 1` or `3`), regex, cluster and limit-app modes. The queue does not yet support cancellation while waiting, and Sentinel Java 1.8.8 has further cluster-node accounting, priority occupancy, token-cache eviction, and circuit-breaker internals; distributed and bursty behavior is not fully equivalent. `APILevel` stays unavailable because both Java `getApiLevel` methods return `null`. Connect an Apollo watcher by calling `Update` when all three rule values are available.
