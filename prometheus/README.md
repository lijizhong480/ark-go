# prometheus

Independent Go module for `ark-prometheus-core` metrics. `Registry` exposes counters, millisecond histograms and live gauges at `Handler()`; every business series receives `push_tag="biz"`. `HTTPRecorder` preserves the Java HTTP metric names and labels. `RegisterExecutor` exports the Java thread pool gauge names from a caller supplied live snapshot.

`Config.MaxTagValues` limits distinct `key=value` pairs across all meter types in this registry; zero disables the limit, matching Java's default disabled filter. The Go check is atomic. `HTTPOptions.MaxAPIs` defaults to 1000. Once a new path exceeds the limit, Java's `exceededLimit` flag maps every later request to `other`, including previously observed paths; the Go recorder follows that behavior. Route templates should be passed when available.

The exporter uses the Prometheus text format without an external client dependency. Millisecond observations are exported as cumulative histogram buckets, sum and count. `ObserveMillisWithPercentiles` and `TimerRecordHistogram` additionally publish p50/p95/p99 as a separate `<name>_quantile` gauge family with a `quantile` label. Keeping quantiles separate preserves a valid Prometheus histogram family for the original metric. Registration reserves the derived `_bucket`, `_sum`, `_count`, and, when used, `_quantile` names so explicit metrics cannot collide. `TimerRecord` publishes p99, while ordinary `ObserveMillis` leaves quantiles off. Go computes these values from the latest 1024 observations per series; Micrometer 1.6.4 uses a rolling HdrHistogram, so percentile numbers can differ around window boundaries and at high volume. JVM/dependency gauges are not reproduced here.
